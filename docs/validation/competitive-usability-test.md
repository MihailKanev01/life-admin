# Competitive Usability Test — Context vs Reminder

## Purpose

Test whether Life Admin provides a meaningful advantage over a generic Reminder/Calendar workflow.

This is the highest-value validation question created by the current secondary research.

## Test setup

Show the participant two ways to handle the same scenario:

**Scenario**
> Your car insurance expires on June 14. You have the insurance PDF, last service information, payment amount, and the car itself.

### A — Generic tool
Ask the participant to imagine or use a normal Reminder/Calendar:
- create the reminder;
- decide where to keep the PDF;
- find the car's previous service information;
- determine what else is related to the insurance.

### B — Life Admin
Use the prototype:
- Quick Add the same sentence;
- review proposed context;
- open Mazda 6;
- find insurance, document, service history and payment.

## Do not explain the intended difference

The moderator must not say:
- that Life Admin is “contextual”;
- that Things are supposed to solve this;
- that documents are connected;
- what the participant should notice.

Ask:
> “Which setup would you rather use for this kind of thing, and why?”

Then:
> “What, if anything, was easier or harder?”

## Measures

Record:

| Measure | What to capture |
|---|---|
| Time to first useful action | Seconds |
| Wrong turns | Count |
| Help requests | Count |
| Information needed to act | Missing/available |
| Confidence | 1–5 |
| Preference | A / B / No preference |
| Switching cost | Low / Medium / High |
| Main reason | Participant's own words |

## Decision rule

This test does **not** pass based on preference alone.

A strong positive signal requires repeated participants to independently say that Life Admin:
- reduces uncertainty;
- makes related information easier to retrieve;
- avoids maintaining multiple lists/folders;
- makes the next action clearer.

A negative signal is equally important:

If participants say:
- “I can already do this with Reminders,”
- “I don't need the extra context,”
- “This is more work than my current setup,”

then the differentiation hypothesis must be revised.

## Guardrails

- Do not present synthetic scores as real participant evidence.
- Do not recruit from only one user profile.
- Do not ask for real bank credentials, medical records, passwords or identity documents.
- Use demo content during testing.
